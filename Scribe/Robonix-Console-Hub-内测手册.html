Robonix Console 与 Robonix Hub 内测手册

安装、配置机器人、运行与版本管理

版本 0.1.0-beta.27 · 2026-10-04

1　概述

Robonix Console 是安装在机器人上的程序，用于管理这台机器人上的 Robonix。用户在浏览器中通过它的 Web UI 进行操作：从软件包目录安装技能、服务和原语，修改配置，启动和停止 Robonix，查看日志，以及升级 Robonix。配置的每次修改都可以保存为版本，之后可以对比和回滚。账户、软件包目录和云端备份由 Robonix Hub（hub.robonix.ai）提供。本手册以一台 Webots 仿真机器人为例，按实际使用顺序介绍各项操作。

不安装也可以先试用：在线演示 https://hub.robonix.ai/demo/ 是一个真实运行的 Robonix Console，打开即可使用全部页面，所做的修改只保存在当前浏览器中。

截图中红框旁的编号对应正文中的 ①②③。内测按第 3 节的顺序进行，遇到的问题按第 4 节提交。

2　组成

Robonix Console 和 Robonix Hub（hub.robonix.ai）是两个独立的程序，区别如下表所示。Robonix Console 侧栏中，“Robonix Hub”一组的页面（目录、我的机器人、个人主页和用量）显示的是云端的内容。

Robonix ConsoleRobonix Hub
位置机器人上，端口 4880（默认只能在机器人上访问）hub.robonix.ai
用途管理所在机器人的部署、运行、日志和更新账户、软件包目录、云端备份、反馈
能否修改机器人能不能

Robonix Console 左上角显示“Robonix Console”和机器人的主机名，Robonix Hub 左上角显示“Robonix Hub”。登录 Robonix Console 使用的是 Robonix Hub 账户。

3　内测流程

内测按以下顺序进行，每一步对应本手册的一节。没有机器人时，可以先在在线演示中熟悉各个页面。

  1. 注册账户，或按邀请邮件激活账户（第 5 节）。
  2. 在机器人上安装 Robonix Console，并填写模型服务（第 6 节）。
  3. 打开 Robonix Console 并登录（第 7 节）。
  4. 从目录安装 Webots 仿真 TIAGo 的整机配置，修改一项参数，添加一个技能，保存为新版本（第 8 节）。
  5. 构建软件包，启动仿真和 Robonix，查看日志，用 robonix-client 连接机器人并发送一条任务（第 9 节）。
  6. 对比两个版本，回滚到旧版本（第 10 节）。
  7. 把部署上传到云端，生成分享链接（第 12 节）。
  8. 让 AI 机器人配置助手检查当前配置，并通过它修改一项参数（第 13 节）。

每一步遇到的错误、不符合预期的结果和看不懂的界面文字，都通过反馈提交（第 4 节）。

4　反馈问题

测试中遇到的问题和建议，都通过页面上的反馈提交，Robonix Console 和 Robonix Hub 都可以提交。

4.1　提交反馈

  1. 点左侧栏底部、账户名右侧的反馈按钮 ①。手机上反馈按钮在页面右上角。
  1. 在“反馈对象” ① 中选择 Robonix、Robonix Console 或 Robonix Hub。不确定时选 Robonix Console。
  2. 在描述框 ② 中写明看到的现象、期望的结果，以及出问题前做的操作。
  3. 检查随附信息。在 Robonix Console 提交时，反馈附带系统与硬件、版本、最近的日志和“Robonix Console 设置”；点“查看” ③ 阅读原文，取消勾选的项不会发送。“当前部署清单” ④ 默认不勾选，勾选后其中的密钥会替换为占位符。
  4. 点“发送” ⑤。

点“查看” ① 展开的 ② 就是将要发送的原文：

发送成功后，对话框显示“已发送。感谢您的反馈。”

在 Robonix Hub 提交时，反馈附带浏览器信息。

4.2　反馈内容要求

  • 一条反馈只说一个问题。
  • 写清复现步骤，具体到点了哪个按钮、填了什么。
  • 页面上有报错时，原样抄下报错文字。
  • 运行相关的问题，保留“最近的日志”的勾选。
  • 界面文字不通顺、步骤需要在终端或手动改文件才能完成，也请反馈。

4.3　离线提交反馈

Robonix Console 无法连接 Robonix Hub 时，反馈对话框提供“下载反馈包”。下载的文件包含同样的内容，可以另行发给维护者。

4.4　反馈的处理

  • 反馈和附件保存 180 天，仅管理员可见。
  • 每个账户每天最多提交 20 条。

4.5　使用说明与服务状态

Robonix Console 的使用说明放在 Robonix 开发手册中，网址为 https://book.robonix.ai/hub，内容包括账户、安装、配置机器人、运行、目录与云端，以及反馈问题。这部分文档在 beta 测试结束后上线，内测期间以本手册为准。Robonix Console 和 Robonix Hub 的页面底部，“使用说明”都链接到这里。

页面底部的“服务状态”打开 https://hub.robonix.ai/status，显示各项服务是否正常。网站打不开或明显变慢时，先看这一页。

5　注册账户

在 Robonix Hub 登录页点“注册”，或直接打开 https://hub.robonix.ai/auth/registration：

  1. 填写邮箱、名字和密码，点“注册”。密码至少 10 位。
  2. 邮箱会收到一封验证码邮件，在页面中输入验证码，确认邮箱。
  3. 阅读个人信息出境告知。由于服务器位于中华人民共和国境外，页面要求逐项勾选三项后才能继续：年满十八周岁 ①、同意将个人信息提供至位于中华人民共和国境外的服务器 ②、同意许可协议 ③。点“阅读许可协议全文”可查看协议原文。同意后，可在个人主页查看同意记录，或点“发送到邮箱”取得一份副本。
  4. 等待管理员审核。内测期间，注册的账户经管理员审核通过后才能使用，通过后会收到邮件。

账户也可以由管理员邀请开通。收到邀请邮件后，打开邮件中的链接，输入邮件中的验证码（72 小时内有效），在同意页勾选上述三项，再设置密码。

注册或激活后，可在账户设置中绑定身份验证器，用于二次验证。

不同意时，点“不同意并退出”，账户不会开通：自行注册时填写的信息，以及管理员录入的邮箱和姓名，都在 30 天后删除。许可协议更新后，需要在 Robonix Hub 上重新同意，之后才能继续使用网站和登录 Robonix Console。账户可在网站的个人主页注销，注销 7 天后删除全部数据。

6　安装

6.1　安装命令

Robonix Hub 首页的“在机器人上安装 Robonix Console”卡片给出一行安装命令和“复制”按钮。命令形式如下：

curl -fsSL https://hub.robonix.ai/install | bash

在机器人上以运行 Robonix 的普通用户身份执行该命令，不要使用 root 或 sudo。

6.2　安装过程

安装过程分为 8 步，安装脚本在每一步显示编号和进度。

步骤内容
1 检查这台机器人显示用户、处理器架构、系统版本、云端地址和安装位置
2 系统软件包检查 git、curl、gpgv、xz、python3-venv 和 whiptail，缺少时安装；安装脚本只在这一步询问一次 sudo 密码
3 许可协议先校验发布签名，再在终端中央的窗口中显示英文许可协议；用方向键或触控板滚动，Tab 切换到“Agree”和“Cancel”，选择“Agree”后继续
4 下载按这台机器人的架构下载 Robonix Console，校验 sha256 和签名，任一项不符即停止
5 Robonix已安装 robonix 时直接使用；未安装时把源码下载到 ~/.local/share/robonix-console/robonix，用 robonix 自带的 make install 安装，耗时较长。下载优先经过国内镜像，失败时再直连；构建时只占一行，滚动显示最新的输出，完整日志在 robonix-build.log
6 服务将 Robonix Console 作为当前用户的 systemd 服务运行，并设为开机自启
7 基本配置询问 Pilot 和 AI 机器人配置助手使用的模型服务，见下文
8 完成确认 Web UI 已响应，并给出访问地址

6.3　基本配置

第 7 步配置 Pilot 和 AI 机器人配置助手使用的模型服务，共三项：VLM 终端 URL（兼容 OpenAI 的 API 地址，例如 https://api.openai.com/v1）、VLM KEY（密钥）和 VLM 模型（模型名），对应变量 VLM_BASE_URL、VLM_API_KEY 和 VLM_MODEL。这台机器人上尚无这三项时，安装脚本询问 Set it now? [Y/n]：直接回车，依次填写三项，密钥输入时不显示；输入 n 则跳过，之后在 Robonix Console 的“设置”页填写。这台机器人上已有这三项，或安装前已在终端中设置了同名环境变量时，安装脚本先列出现有的值（密钥只显示末 4 位），询问 Keep these? [Y/n]：直接回车保留；输入 n 后逐项填写，某一项直接回车即保留原值。

这三项只保存在这台机器人上，不会上传，之后可以在“设置”页的“机器人环境变量”中修改。

拒绝许可协议时，安装立即结束，机器上不留下任何文件。Robonix Console 安装在用户主目录下：程序位于 ~/.local/bin/robonix-console，数据位于 ~/.local/share/robonix-console。

x86_64 和 aarch64（包括 Jetson）机器使用同一条命令安装，安装脚本自动选择对应的版本。

0.1.0-beta.26 及以前安装的程序名为 robonix-hub。自动更新到新版本后，它自行改用上述新名称，部署、历史和登录状态保持不变；重新执行安装命令也会完成同样的迁移。

7　登录

7.1　打开 Web UI

Robonix Console 默认只监听 127.0.0.1:4880。在机器人自身的桌面上，用浏览器打开 http://127.0.0.1:4880。从另一台电脑访问时，先建立 SSH 隧道，再在该电脑的浏览器中打开同一地址。

ssh -L 4880:127.0.0.1:4880 <用户>@<机器人地址>

7.2　登录账户

登录前，页面显示登录表单。填写 Robonix Hub 账户的邮箱 ① 和密码 ②，点“登录” ③。账户已开启二次验证时，下一步还需输入验证码。不登录也可以点表单下方的“浏览软件包目录”查看目录。

尚未在 Robonix Hub 上同意许可协议的账户无法登录 Robonix Console，页面会提示先到网站上同意。同一台机器人上，不同用户可以各自登录。登录状态保留 7 天，Robonix Console 重启后不需要重新登录。点左侧栏底部的账户名，在菜单中点“退出登录”可结束本次登录；手机上账户菜单在页面右上角。

7.3　页面布局

登录后，左侧栏顶端显示“Robonix Console”和机器人的主机名，下方分为两组。“这台机器人”一组依次为概览、配置、历史、日志、更新和设置；“Robonix Hub”一组显示云端的内容，依次为目录、我的机器人、个人主页和用量。左侧栏底部依次是账户菜单、反馈按钮和收起侧栏的按钮，账户菜单中有语言、外观和退出登录。页面右侧是 AI 机器人配置助手（第 13 节）。

手机上没有左侧栏。页面顶部右侧是反馈按钮和账户菜单，底部的标签栏切换这台机器人、目录、我的机器人和个人主页，这台机器人各页面的标签排在“这台机器人”标题下方。

8　配置机器人

一台机器人的全部配置写在一份部署清单（manifest）中，包括驱动硬件的原语（primitive）、使用的服务（service）和技能（skill），以及系统服务的参数。部署清单、版本历史和相关文件组成机器人上的一个部署，见第 11 节。

配置机器人有两种方式。软件包目录中已有该机器人的整机配置时，从目录安装后按需修改；目录中没有时，从空白开始编写。

8.1　从目录安装整机配置

打开“目录”，选择“机器人”分类 ①，在搜索框 ② 中输入型号。Webots 仿真的 TIAGo 在目录中的名称是 robot.pal_robotics.tiago_webots ③。

点开该条目，页面显示其说明、版本和仓库。点“安装到这台机器人” ①。

确认对话框列出将要安装的内容。整机配置除部署清单外，还包括与之一同存放的本地软件包和仿真脚本，Robonix Console 会一并下载。当前部署为空时，文件放入当前部署；当前部署已有配置时，Robonix Console 新建一个部署并切换过去，原有部署保持不变。下载期间按钮旁显示经过的镜像、进度和速度；某个镜像不通时，Robonix Console 自动改用下一个，最后直连 GitHub。

安装完成后，页面跳转到“配置”页，这份配置已保存为第一个版本。

8.2　配置页

“配置”页顶端一栏始终可见：左侧是分区导航 ①，点击即跳到对应分区；右侧是“编辑 YAML”和“保存为新版本” ③。下方各分区依次为：

  • 系统服务：Robonix 自身的 atlas、executor、pilot、liaison、soma、vitals 和 scene。atlas、executor 和 soma 标为“必需”，不能关闭；其余各项右侧有开关 ②，关闭后写为 status: disabled，启动时跳过。
  • 自带服务：Robonix 源码中自带的服务，例如语音、记忆和验证器，路径以 ${ROBONIX_SOURCE_PATH} 开头。开关打开即加入部署。
  • 原语、服务、技能：部署使用的软件包，每个软件包同样有开关。
  • 环境变量：只对这一份部署生效的环境变量。
  • 发布信息：把部署发布到个人主页时使用的说明。

8.3　修改参数

点开任意一项即可修改其配置。软件包或服务提供严格格式的配置说明（config.spec）时，配置显示为分组表单：每个参数占一行，右侧显示当前值，未设置时显示默认值；带分组的参数收在分组 ① 中，分组右侧显示参数总数和已设置的个数；点开一行 ② 才显示输入框和说明，说明较长时只显示两行，点“更多” ③ 展开全文。已设置的参数名后有一个圆点，“改回默认”可清除设置。

参数的值是部署中另一个条目的名称时（例如建图服务的激光雷达由哪个原语提供），点开该行 ① 显示一个选择框 ②。下拉列表中，提供所需能力约定的条目排在最前面，其后是其他条目。提供方不在本部署中（例如运行在另一台机器上）时，选列表最后的“手动填写…”，再输入提供方的名称。

没有严格格式说明的软件包，配置按键值对列出，可以直接修改、删除和添加；“查看说明”显示软件包附带的说明原文。修改后，页面顶端的“保存为新版本”显示未保存的修改数。

8.4　机器人环境变量

部署清单在必填参数中引用了某个变量，而该变量在机器人环境变量和部署中都没有设置时，“配置”页和“概览”页显示提示 ①，列出这些变量。点“设置” ② 可以直接填写。

在对话框中填写各变量的值 ①。名称中带有 KEY、TOKEN、SECRET 等字样的变量默认遮住，点眼睛图标 ② 显示。保存后，这些值写入机器人环境变量，与安装时的基本配置相同，不会上传。

8.5　添加技能

每个分组右侧都有“添加软件包”，软件包可以来自软件包目录，也可以是部署中的本地软件包。在“技能”分组点“添加软件包” ①，搜索 find_object ②，点搜索结果将其加入部署。已在部署中的软件包标有“已在部署中”，不能重复加入。

8.6　保存为新版本

点页面顶端的“保存为新版本”。对话框中的版本号 ① 在上一版本的基础上自动递增，修改说明 ② 为必填项。下方显示修改前后的对比 ③，改动的行高亮显示，其余行折叠。

8.7　从空白开始编写

目录中没有合适的整机配置时，先在“设置”页新建一个部署，只填名称即可（第 11 节）。新部署的“配置”页是空的。按上文的方法逐个添加软件包，然后保存为第一个版本。

机器人本身的原语通常尚未发布到软件包目录，而是放在部署中的某个子目录里。在“添加软件包”对话框中选择“本地软件包”，对话框列出部署中所有包含 package_manifest.yaml 的子目录，选中其中一个即可加入部署。

需要直接修改部署清单时，点“编辑 YAML”。编辑器支持语法高亮和错误提示，并保留文件中的注释。点“返回表单”回到分组视图。

9　运行

9.1　下载与构建软件包

部署中引用的软件包需要先下载和构建，Robonix 才能运行。打开“更新”页，页面下方的软件包列表 ① 显示每个软件包的已安装版本和最新版本。随配置一起安装的软件包显示为“本地目录”，尚未下载的远程软件包显示为“未下载”。有更新的软件包旁有“查看改动”，点开列出已安装版本与最新版本之间的提交记录。点“更新全部软件包” ②，Robonix Console 拉取代码并逐个构建。

任务开始后，页面上方显示任务日志，任务完成后显示结果。构建失败时，日志中给出出错的软件包及原因。缓存损坏时，先点“清理缓存”，再点“更新全部软件包”。

9.2　Webots 仿真

仿真机器人与真机的操作相同，区别是启动 Robonix 之前需先启动 Webots 仿真。仿真脚本随整机配置安装在部署中。在机器人上执行：

bash <部署路径>/sim/start.sh

部署的路径显示在“设置”页的部署列表中。仿真启动后，再在概览页点“启动”。

9.3　启动与停止

回到“概览”，点“启动”。状态依次显示“启动中”和“运行中” ①，按钮变为“停止” ②。同一张卡片下方的“连接 robonix-client”给出机器人地址 ③ 和 Atlas 端口 ④，供连接客户端时使用。

两套 Robonix 会占用相同的端口，因此一台机器人同一时间只能运行一个部署。另一个部署正在运行时，概览页显示正在运行的部署的名称，“启动”不可用；点“停止它”即可停止那个部署的 Robonix。

运行失败时，状态显示“失败”，下方给出 rbnx 报告的失败原因。开机自启可以在概览页开启，同一时间只能有一个部署设为开机自启。

9.4　查看日志

点“查看运行日志”或“日志”标签打开日志页。左侧列出最近几次运行 ①，每次启动对应一条，默认保留 10 次。日志上方每个组件各有一个标签，“rbnx 输出” ② 是启动过程本身的输出。筛选框 ③ 按关键字过滤日志，“跟随最新” ④ 使页面随新日志自动滚动到底部。

日志较长时，页面先显示最后一部分，并提供“显示全部”和“下载完整日志”。截图为点“显示全部”后的页面。

9.5　连接 robonix-client

客户端需要概览页上的机器人地址和 Atlas 端口（见上文截图）。地址有多个时任选一个，点击即可复制。Liaison 地址留空即可，客户端会通过 Atlas 获取。

某个组件只监听本机时，其他机器上的客户端无法连接，概览页会给出提示和“允许其他机器连接”按钮。点击并确认后，Robonix Console 将该组件的监听地址改为 0.0.0.0 并保存为新版本，下次启动时生效。此功能只应在可信网络中使用。

在另一台电脑上启动 robonix-client，在浏览器中打开 http://127.0.0.1:7860。在“机器人主机” ① 中填入概览页给出的机器人地址，在“Atlas 端口” ② 中填入 Atlas 端口，连接成功后，客户端显示“已连接” ③。

输入任务并发送。下例让机器人用头部相机拍照并描述前方场景，回复 ① 给出结果，右侧“当前目标”显示已完成 ②。

10　版本管理

10.1　版本与对比

每保存一个新版本，“历史”页就新增一条记录，最新的记录在最上方，“当前”标记正在使用的版本 ①。点任意旧版本 ②，“与当前对比” ③ 显示该版本与当前清单的差异。

10.2　回滚

“回滚到此版本”把部署清单恢复为该版本的内容。回滚前，页面会要求再次确认。回滚不新增版本。Robonix 正在运行时，回滚在重新启动后生效。

机器人上的清单文件被直接修改时，Robonix Console 会在下次保存或回滚之前先将改动记为一个版本，因此手动修改不会被覆盖。

10.3　导出与导入

“历史”页下方的“导出历史”把这台机器人的全部版本导出为一个文件，“导入历史”用文件替换现有历史。这两项用于备份，以及把版本历史迁移到另一台机器人。

11　部署

部署是机器人上运行 rbnx boot 的一个目录，一套配置的全部文件都在其中：

内容说明
robonix_manifest.yaml部署清单
primitives/、services/本地软件包，即部署清单中以本地路径引用的软件包
scripts/、config/、sim/ 等整机配置附带的脚本、配置文件和仿真场景

安装 Robonix Console 时创建默认部署，目录为 ~/.local/share/robonix-console/deployments/default，名称为 Default deployment。每个部署的版本历史由 Robonix Console 保存，不需要手动管理，见第 10 节。全部部署列在“设置”页的“部署”一节。

一台机器人可以有多个部署，各部署相互独立，不会覆盖。同一时间只有一个当前部署：概览页的启动与停止、“配置”页的修改、“历史”页的回滚，都作用于当前部署。概览页标题“这台机器人”旁边的下拉框用于切换当前部署。

以下情况会新增部署：

  • 从目录安装整机配置或从云端下载部署时，若当前部署为空，则放入当前部署；若已有配置，则新建一个部署放入，并切换过去，原部署保持不变。
  • 在“设置”页新建。只填名称时，Robonix Console 在默认部署旁边创建一个空目录；同时填写已有目录的路径时，例如此前在命令行中手动搭建的部署，Robonix Console 直接使用该目录。

例如，新安装的 Robonix Console 只有一个空的部署 Default deployment。从目录安装 TIAGo 的整机配置，配置放入 Default deployment。再安装 Piper 双臂的整机配置时，Default deployment 中已有配置，于是 Robonix Console 新建部署 dual_piper 放入 Piper 的配置，并切换过去。需要运行 TIAGo 时，在概览页的下拉框中切换回 Default deployment，再启动。

部署可以在“设置”页重命名和删除。删除时，由 Robonix Console 创建的目录连同文件一起删除，用户指定的已有目录只从列表中移除，文件保留。最后一个部署不能删除。

12　云端备份

云端备份是一个部署上传到当前账户云端空间后的备份，包括部署清单和全部版本（最多保留最新的 200 个）。每个部署各有一份备份：同一台机器人上的几个部署分别上传，得到几份备份，互不覆盖。备份可以下载到其他机器人上，也可以生成分享链接（第 12.1 节）。

概览页的“云端备份”卡片作用于当前部署，卡片上写明了部署名称。点“上传此部署” ① 后，页面先列出将要发送的内容：主机名、硬件、系统和版本数量，以及将被替换为占位符的密钥。确认后，Robonix Console 才开始上传。同一部署再次上传时，新的内容替换它在云端的上一份备份。换用其他账户登录后上传，备份存入该账户的空间，互不影响。

“从云端下载” ② 列出当前账户空间中的云端备份，每份以“机器人 · 部署”标识。选中一份后，它的部署清单和全部版本默认下载到新的部署，当前部署保持不变，下载完成后可以选择切换过去。勾选“改为覆盖当前部署”时，对话框给出警告，下载后当前部署的部署清单和全部版本会被替换。

Robonix Hub 的“我的机器人”页列出已登录本账户的机器人及其在线状态，可在此让某台机器人退出账户；上传的备份列在同一页的“云端备份”下，每份注明来自哪个部署，只能查看和下载，修改需在 Robonix Console 中进行。

12.1　分享部署

Robonix Console 和 Robonix Hub 的“我的机器人”页中，每个已上传的云端备份旁都有“分享”按钮；部署尚未上传时，先在概览页的“云端备份”卡片中上传。点击后，对话框先列出部署清单中检测到的密钥及替换方式，确认后生成分享链接，形如 https://hub.robonix.ai/d/。分享出去的是密钥已替换为环境变量引用的副本，自己的记录不受影响。已分享的备份旁显示“已分享”，点开可以复制链接或停止分享；停止后链接立即失效。分享的部署同时列在个人主页“收藏与分享”的“分享的部署”中，以机器人、部署和版本号标识，点击打开分享页。

拿到链接的人无需登录即可查看分享页：名称、分享者和时间、使用的软件包和部署清单。分享页不出现在目录和搜索结果中。在线演示中的修改只保存在访客的浏览器里，因此演示中不提供分享。在 Robonix Console 概览页的“云端备份”卡片中点“导入分享链接”，粘贴链接后点“打开”，页面上有“安装到这台机器人”：当前部署为空时放入其中，否则新建一个部署。分享只包含部署清单，原作者放在自己部署中的本地软件包不在其中，安装后需自行准备。

12.2　用量

侧栏的“用量”页显示本账户在 Robonix Hub 中占用的存储空间；手机上从右上角的账户菜单进入。页面列出已用空间和上限、各类别和各份云端备份的占用，以及各项上限。目前只有云端备份计入用量。

目前的上限为内测阶段的初步设定：每个账户 10 MiB，最多 50 份云端备份，每份保留 200 个版本，单份部署清单不超过 256 KiB。上传会超出存储上限时，Robonix Console 提示空间不足，云端已有的数据保持不变；删除不需要的云端备份后可以继续上传。保存或导入超过 256 KiB 的部署清单时，Robonix Console 拒绝并提示删减。

13　AI 机器人配置助手

Robonix Console 右侧的“AI 机器人配置助手”用一句话完成配置相关的工作：检查当前配置有没有问题、修改参数、添加或停用软件包、回滚版本、启动或停止 Robonix、查看运行日志、按能力在目录中查找软件包、查看云端用量等。第一次打开 Robonix Console 时，桌面端的助手面板默认展开；收起后，右下角的“AI 机器人配置助手”按钮可以再次打开它。手机上助手以全屏面板显示。

13.1　模型服务

助手使用机器人上为 Pilot 配置的模型服务，即“设置”页“机器人环境变量”中的“VLM 终端 URL”“VLM KEY”和“VLM 模型”三项，对应 VLM_BASE_URL、VLM_API_KEY 和 VLM_MODEL。三项未填写时，助手面板提示先填写，并提供“去设置”的链接。模型服务需兼容 OpenAI 的 Chat Completions 接口并支持工具调用。

13.2　使用方式

在面板底部的输入框中输入要做的事，按回车发送；空白对话中也可以直接点示例。助手先调用工具读取所需的信息，面板中逐条列出它调用的工具，然后给出回答。

会改变机器人状态的操作，例如修改配置、添加软件包、回滚版本、启动或停止 Robonix、上传到云端，助手不会直接执行，而是先显示确认卡片：写明要做的操作，修改部署清单时附带修改前后的对比。点“同意”后才执行，点“拒绝”则放弃，助手会说明操作没有执行。修改配置时，助手把结果保存为新版本，说明中带有“(AI)”，可以在“历史”页回滚。设置机器人环境变量时，值由用户在确认卡片中填写，模型看不到这个值。

删除部署、用导入覆盖历史、账户相关的操作不对助手开放。点面板标题栏的刷新图标开始新的对话；对话只保存在当前浏览器标签页中。

在线演示中的助手使用 Robonix Hub 提供的模型，每个访客有使用额度，用完后需等待一段时间；演示中同意的修改只保存在访客自己的浏览器中。

14　目录与收藏

“目录”按“技能”“服务”“原语”“机器人”“全部”“收藏”分类，可以按热度、最近更新时间或名称排序，也可以搜索。目录、软件包页和能力约定无需登录即可查看，Robonix Console 和 Robonix Hub 均如此；收藏和安装需要登录。

软件包页依次显示类别、版本、说明和统计数据，然后是所提供的能力约定，最后是详情和仓库的 README。详情中的标签可以点击，点击后目录只显示带这个标签的软件包。点“收藏”可收藏软件包。收藏内容在 Robonix Console 和 Robonix Hub 中保持一致，可在目录的“收藏”分类和网站个人主页的“收藏的软件包”中查看。在 Robonix Console 中打开软件包页时，页面还有“添加到这台机器人”，作用与“配置”页的“添加软件包”相同。

机器人整机配置的页面不显示能力约定，而是显示“使用的软件包”：按原语、服务、技能分组，列出部署清单中的全部软件包。目录中有对应条目的，点击打开其软件包页；其余的链接到各自的仓库，或标注为“本地软件包”，即随整机配置存放在同一仓库中的软件包。已停用的软件包标注“已停用”。

14.1　能力约定

“提供的能力约定”把软件包提供的能力约定按名称的层级画成一棵树，每条约定旁标出传输方式，例如 rpc、topic_out、rpc_server_stream。点树中的一条约定 ①，打开该约定的说明。一条约定下还有其他约定时（例如 explore 下的 cancel 和 status），它的方框同时标出传输方式和其下约定的数目，点开后在说明之后列出其下的约定。

说明页列出传输方式 ①、版本、接口文件和定义方，再按数据流向列出接口字段：服务分为“输入（请求）”② 和“输出（响应）”③，话题标为发布或订阅的消息。每个字段列出类型、名称和注释。字段的类型是另一条消息时，点击类型名，当前窗口上层会弹出该消息的字段，可以逐层查看。点“查看源文件” ④ 可阅读约定定义和接口文件的原文。

14.2　只读 API

Robonix Hub 提供只读的 REST API，地址前缀为 https://hub.robonix.ai/api/v1。目录、软件包、统计数据和能力约定无需令牌；账户信息、收藏和机器人需要个人访问令牌。令牌在个人主页的“API”一节生成，只显示一次，有效期 90 天，可随时吊销。请求时在请求头中写 Authorization: Bearer <令牌>。“API”一节列出了全部接口和对应的 curl 命令，点“试一下”可直接查看返回结果。接口说明见 https://hub.robonix.ai/api/v1/openapi.json。

15　更新与卸载

15.1　Robonix Console 的自动更新

Robonix Console 在每次启动时和此后每 6 小时检查一次 hub.robonix.ai 上的新版本。发现新版本时，Robonix Console 自动下载安装并重启，部署、版本历史和日志全部保留。Robonix 本身和正在运行的部署不受影响，Robonix Console 重启期间机器人照常运行。

新版本无法启动时，Robonix Console 自动退回旧版本，并在“更新”页记录原因。

以下情况下 Robonix Console 不自动更新，只在“更新”页提示：

  • 新版本的许可协议有变化：需要在“更新”页阅读并接受新协议后，点“更新到”该版本。
  • 有构建或升级任务正在运行：任务结束后再更新。
  • 关闭了“更新”页的“自动更新”开关。

“更新”页的“Robonix Console”一栏显示当前版本、最新版本和最近的更新记录（已安装、已确认、已退回），并提供“检查更新”和“自动更新”开关。有新版本时，这一栏直接列出从当前版本到新版本之间每个版本的更新说明。

15.2　升级 Robonix

“更新”页的“robonix”一栏显示这台机器人上 Robonix 的版本和源码位置，并列出 Robonix 的全部发布版本，标出最新版、预发布版和当前版本。如需指定任意一次提交，填写它的提交 ID。选择目标版本后，下方先显示当前版本和目标版本的提交 ID、目标版本的更新说明，以及两者之间的提交记录（提交较多时默认收起，点开查看）；确认后点“安装”，Robonix Console 依次停止 Robonix、切换源码、重新编译安装，再重新构建所有软件包。任一步骤失败，Robonix Console 都会退回原来的版本。升级在后台进行，关闭页面不会中断升级。

15.3　重新安装与卸载

在已安装 Robonix Console 的机器上再次执行安装命令即可重新安装，部署和版本历史全部保留。许可协议未变时，安装脚本不再询问。

卸载命令如下。卸载会停止并删除 Robonix Console 服务，但保留部署、版本和日志。

curl -fsSL https://hub.robonix.ai/install | bash -s -- --uninstall

同一版协议同意过一次后，再次安装不再显示；要重新查看，在安装命令末尾加上 -s -- --show-eula。无人值守安装时，先阅读许可协议 https://hub.robonix.ai/download/EULA.md，再在安装命令末尾加上 -s -- --accept-eula。

16　设置

“设置”页分为下载镜像、运行、访问和机器人环境变量四组，每一行左边是设置项和说明，右边是选项。修改任何一项后，页面底部出现“有未保存的更改”：点“保存设置”一次保存全部修改，点“放弃修改”恢复原值。页面最下方的“部署”一节不在其中，新建、切换、重命名和删除都立即生效。

17　管理后台

本附录供 Robonix Hub 的管理员使用，普通内测账户看不到这些页面。管理后台用于管理账户、反馈和站点设置。管理员登录网站后，侧边栏下方出现“管理”一组，依次为概览、用户、反馈、邮件、审计日志、目录同步、监控和站点设置。进入管理后台需要两步验证：账户未绑定身份验证器时，页面提示先在“账户与安全”中绑定，然后重新登录。

17.1　概览

概览页显示活跃用户、待激活、已禁用和管理员的人数，机器人、部署快照和目录中软件包的数量，24 小时内被拒绝的请求数，以及上次目录同步的时间与成败数、待删除的账户数和服务版本。

17.2　用户

  1. 在“邀请用户”中每行填写一位：邮箱，姓名。
  2. 勾选“已告知上述每一位并取得其同意”。不勾选时无法发送。
  3. 点“发送邀请”。系统为每人创建账户并发送激活邮件，链接 72 小时内有效。结果逐行显示为已邀请、已存在或无效。

邀请框下方是用户列表，可以按邮箱或姓名搜索，并按全部、活跃、待激活、已禁用筛选。列表显示角色、状态、邀请邮件是否送达、机器人数量、云端存储用量、最近活动和创建时间，点列名可以排序。

点每行末尾的“…” ① 打开操作菜单。菜单只列出对该账户当前可用的操作，管理员不能对自己的账户操作。

操作说明
重发邀请账户尚未激活时，重新发送激活邮件
强制下线结束该账户的全部登录会话
重置两步验证清除已绑定的身份验证器，对方下次登录后重新绑定
禁用 / 启用禁用后无法登录，已登录的会话同时失效；启用后恢复
设为管理员 / 取消管理员调整账户角色，对方需要重新登录
设置存储配额为该账户单独设定云端存储上限，留空使用默认值
删除账户永久删除账户及其上传的全部机器人和版本历史，无法撤销；需要输入对方的邮箱确认
撤销删除账户本人申请删除、尚未执行时，取消这次删除

除“重发邀请”外，这些操作要求最近 15 分钟内登录过；超过时页面转到登录页重新验证，完成后回到原页面再操作一次。唯一的管理员不能被禁用或取消管理员。

17.3　反馈

反馈页列出用户提交的反馈，每条显示状态、时间、反馈对象、提交人、来源机器和附件大小。右上角可以按反馈对象和状态筛选，默认只显示待处理的反馈。

点一条反馈进入详情页。左侧是机器信息和随附的附件，日志等文本附件可以直接查看，过大的文件只显示末尾 512 KiB，也可以下载整个压缩包。右侧“处理”中选择待处理、处理中或已关闭，填写备注后点“保存”。备注仅管理员可见。

17.4　邮件

邮件页分两部分：“邀请与通知”是 Robonix Hub 发出的邀请和反馈通知，“验证和账户恢复邮件”由账户服务 Kratos 发出。每封邮件显示时间、收件人、状态（排队中、发送中、已发送、失败、已放弃）、尝试次数和失败原因。用户说没有收到激活邮件时，先在这里查找。

17.5　审计日志

审计日志记录账户、机器人、令牌和管理操作，每条包括时间、操作人、动作、对象、结果和来源 IP。来源 IP 只保存哈希值。可以按动作前缀筛选，例如输入 admin. 只看管理操作；也可以只看成功或已拒绝的记录。页面底部的“加载更早的记录”继续向前翻。

17.6　目录同步

目录会定期从软件包仓库同步。“立即同步”只重新读取有变化的软件包，“全量同步”重新读取全部软件包。下方的同步记录列出每次同步的起止时间、总数、成功与失败数和方式；有读取失败的软件包时，“读取失败的软件包”列出软件包和原因。

17.7　监控

监控页顶部列出正在触发的告警及其级别。下方的图表可以切换 1 小时、6 小时、24 小时和 7 天的范围，包括请求量、5xx 错误占比、响应时间、被限流的请求、活跃用户、上传过的机器人、CPU、内存、磁盘、数据库连接数、距上次备份的时间和发送失败的邮件。每张图右上角是当前值。

17.8　站点设置

设置项说明
全站只读维护时开启。除管理后台外的所有写操作均被拒绝，登录和退出不受影响；开启期间概览页显示提示
顶部公告显示在每个页面顶部，留空则不显示，最多 300 字
每个 IP 每分钟的请求上限超过后返回 429，一分钟后恢复，范围 30 到 10000
每个 IP 每小时上传机器人的次数上限范围 1 到 1000

修改后点“保存”。每次保存都记入审计日志。
