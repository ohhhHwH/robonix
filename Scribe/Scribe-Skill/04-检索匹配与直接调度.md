# 文档 04｜检索匹配与直接调度

> 阶段 S4：用户问相同/相似问题时，跳过从零规划，直接命中技能并调度 RTDL 执行。

## 阶段目标

打通「问 → 技能命中 → 直接调度」路径：Pilot 规划前先查 `list_skills`，命中则 1 次 tool call 走 S3 实例化并直接 dispatch，未命中才走原规划流程。

## 依赖（前置）

- S3（实例化器）；检索部分可与 S1 并行开发。

## 具体子任务

### 4.1 query → skill 匹配
- 复用 `core/llm_search.py` 的三层检索 + LLM 排序思路，输出「技能」而非「记忆节点」：
  - 先标签/关键字过滤（`task_type`、`scene_type`、`action_type`）。
  - 向量精排（embedding 余弦）。
  - LLM 排序：判定「该 query 是否等价于某技能的 goal_template」。
- 匹配阈值与「未命中」判定可调，避免误触发。

### 4.2 Pilot 规划前先查技能
- 改 `system/pilot/src/memory.rs`（或规划入口）：规划前先调 `list_skills` 做命中判断。
- 命中 → 直接进入 S3 实例化；未命中 → 走既有 `search`/`hybrid_search` 注入上下文 + 从零规划。

### 4.3 直接调度路径
- 命中技能 → S3 实例化 RTDL 树 → 经既有 Executor `execute` 契约 dispatch（不再让 LLM 逐步推导）。
- 保留「安全回退」：执行失败时回退到 Pilot 重新规划。

### 4.4 测试
- 端到端：`问相同问题 → 命中技能 → 直接调度`（对比从零规划，验证 RTDL 轮次/token 下降）；未命中时正常走原流程。

## 所需资源/工具

- `services/memory/memory_service/core/llm_search.py`、`core/retrieve.py`
- `system/pilot/src/memory.rs`、`system/pilot/src/planner.rs`
- `capabilities/system/executor/execute.v1.toml`

## 预期交付物

- 「问 → 技能命中 → 直接调度」端到端路径 + 测试。

## 时间节点（可选）

- 相对估算：约 3–4 人日（检索部分可与 S1 并行）；阻塞 S5。
